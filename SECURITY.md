# 🇬🇧 English

## Reporting a vulnerability

If you find a security vulnerability in any of our projects, **please do not open a public issue, pull request or discussion.** Public reports can expose users before a fix is available.

Report it privately by email to **helpdesk@cubixone.eu** with the subject line `Security report`.

Please include:
- A clear description of the problem
- The repository, module or URL affected
- Steps to reproduce it
- The potential impact (what an attacker could do)
- Screenshots, logs or proof of concept, if you have them

Do **not** include real passwords, tokens or customer data in your report. If you need to show a secret, redact it.

## What to expect

- We will acknowledge your report as soon as possible.
- We will assess the problem and keep you informed of the progress.
- We ask you to keep the issue confidential until a fix is released.
- Once fixed, we are happy to credit you if you wish.

## Scope

This policy covers the code and services published under this organization. Reports about third-party software (frameworks, libraries, hosting providers) should also go to the respective maintainers.

## Exposed secrets

If you notice credentials, API keys, tokens or `.env` files accidentally committed in any repository, report it immediately using the email above. Do not use or share them.

## Good faith

We will not pursue action against anyone who reports a vulnerability in good faith, avoids accessing or modifying data that is not theirs, and does not disrupt our services or our customers.

# 🇵🇹 Português

## Reportar uma vulnerabilidade

Se encontrares uma vulnerabilidade de segurança em qualquer um dos nossos projetos, **não abras uma issue, pull request ou discussão pública.** Reportes públicos podem expor utilizadores antes de existir uma correção.

Reporta em privado por email para **helpdesk@cubixone.eu** com o assunto `Security report`.

Por favor inclui:
- Uma descrição clara do problema
- O repositório, módulo ou URL afetado
- Os passos para o reproduzir
- O impacto potencial (o que um atacante poderia fazer)
- Capturas de ecrã, logs ou prova de conceito, se tiveres

**Não** incluas passwords, tokens ou dados de clientes reais no teu reporte. Se precisares de mostrar um segredo, oculta-o.

## O que esperar

- Confirmamos a receção do teu reporte o mais rapidamente possível.
- Avaliamos o problema e mantemos-te informado do progresso.
- Pedimos que mantenhas o assunto confidencial até a correção ser publicada.
- Depois de corrigido, podemos dar-te crédito, se o desejares.

## Âmbito

Esta política abrange o código e os serviços publicados nesta organização. Reportes sobre software de terceiros (frameworks, bibliotecas, fornecedores de alojamento) devem também ser enviados aos respetivos responsáveis.

## Segredos expostos

Se reparares em credenciais, chaves de API, tokens ou ficheiros `.env` commitados por engano em qualquer repositório, avisa de imediato através do email acima. Não os uses nem os partilhes.

## Boa-fé

Não tomaremos ações contra quem reportar uma vulnerabilidade de boa-fé, evitar aceder ou alterar dados que não são seus e não perturbar os nossos serviços ou os nossos clientes.
